# 产品方向

ZCode 的下一阶段目标是成为一个**能看见、能干预、能验收的 Agent 项目空间**。

用户可以从一个想法开始，不必先知道怎样写 PRD、拆接口、排开发任务或设计验收流程。ZCode 帮助把想法逐步整理成可执行的工程计划，再调用已有 Agent 和工作流完成开发、验证和交付。

## 普通聊天和工程模式

ZCode 保留两种使用方式：

- **普通聊天**：回答问题、处理小改动、使用工具或派一个简单 Agent。过程保持轻量。
- **工程模式**：面对一个需要持续推进的目标，形成项目上下文、阶段、工作项、执行记录、验证证据和交付结果。

不是每个请求都要创建项目。工程模式只在目标需要持续工作、多个步骤、代码改动、验证或用户反复介入时使用。

## 工程模式的核心承诺

1. **能看见**：用户知道项目目标、当前阶段、每个工作项、Agent 状态、依赖、阻塞、文件改动和验证结果。
2. **能干预**：用户可以补充背景、调整方向、回答问题、暂停、恢复、停止、重试或要求重新处理工作项。
3. **能验收**：用户能看到完成了什么、依据是什么、验证覆盖了什么、还缺什么，并能确认是否交付。

## 目标生命周期

```text
想法 → 澄清 → 方案 → 任务计划 → 执行 → 验证 → 待验收 → 交付
```

每个阶段都要有用户能理解的产出。阶段完成不只看 Agent 是否停止，还要看目标、工作项、证据和产物是否足够。

## 复用现有能力

工程模式建立在 ZCode 已有能力之上：

- Agent/Task 负责普通和轻量工作；
- Dynamic Workflow 负责并行、依赖、阶段、报告、产物和恢复；
- Expert Workflow 提供已有的澄清、任务分析、架构拆解、执行和审查阶段；
- Workspace、Git、Diff、Preview 和 checkpoint 承载工程工作面；
- journal、事件和观察投影提供可恢复的运行事实。

工程模式不另建一套 Agent 调度器、后台队列、事件系统或运行时持久化。

## 衡量方向

每次改进都要回答：

- 非开发者是否更容易把想法说清楚；
- 用户是否能少做项目管理和进度追问；
- Agent 的改动和验证是否可追溯；
- 用户是否能在关键节点纠正方向；
- 系统是否能明确区分完成、部分完成、受阻和已交付；
- 简单任务是否仍然快速。
