# ZCode 工程能力基线

## 结论

当前 ZCode 已经拥有支撑工程模式的执行底座：普通 Agent/Task、Dynamic Workflow、Expert Workflow、Workspace、Git、Diff、Preview、后台任务、运行观察和恢复机制都存在。工程模式不需要再建设一套 Agent 调度器。

当前缺的主要是产品组织层：没有把一个工程目标下的阶段、工作项、Agent 执行、文件改动、验证证据和交付决定统一成一个用户可管理的项目空间。

## 已验证的 Dynamic Workflow 能力

在 `328c1a0c0ffaa5a4f65e8fa199af5e4c20706e5f` 源码树上，使用已构建的 Dynamic Workflow runtime harness 实际运行了：

1. 两个 actor 并行执行；
2. 两个结果传递给后续汇总 actor；
3. 汇总 actor 在上游完成后才执行；
4. run 最终结算为 `completed`；
5. 事件包含 actor 创建、节点排队、节点派发、节点结算和 run 结算。

实际得到的汇总输入为 `LEFT-RESULT / RIGHT-RESULT`，最终产物为 `SUMMARY(基于两个结果汇总：LEFT-RESULT / RIGHT-RESULT)`。这证明并行、依赖传递和汇总在当前运行时确实成立。

## 工程模式缺口

| 目标能力 | 状态 | 需要补什么 |
| --- | --- | --- |
| 项目对象 | 当前缺口 | 关联目标、阶段、工作项、run、文件、证据和交付。 |
| 项目简报和验收标准 | 入口缺失 | 将模糊想法整理成用户可确认的范围和完成条件。 |
| 阶段门 | 入口缺失 | 范围、方案、执行和交付的批准/驳回/重开语义。 |
| 项目总览 | 入口缺失 | 将已有运行、任务、Git、产物和验证投影到同一工程视图。 |
| 项目干预 | 部分具备 | 统一追加背景、改工作项、暂停、恢复、停止、重试和重规划。 |
| 验证记录 | 部分具备 | 关联命令、环境、revision、结果和验收标准。 |
| 交付状态 | 当前缺口 | 独立于 run 状态记录部分完成、受阻、待验收和已交付。 |
| 项目级恢复 | 未验证 | 重启后恢复项目总览和可执行干预。 |
